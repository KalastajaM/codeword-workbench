# Codeword Workbench user guide

Installation is in the [README](../README.md). Word lists are covered in [dictionaries.md](dictionaries.md).

## First puzzle

Select **Try a small example**, then **Solve puzzle**. The example deliberately permits alternative solutions. Suggestions appear in teal; confirmed letters have a solid style. Select an alternative and accept a cell, the selected across/down word, or the full suggestion.

**Full-size showcase** loads an original 13 × 13 English codeword with numbers only and no letters given. It is set to solve without a dictionary using **Deep** search. While the search runs, the grid shows its best unverified guess so far; when it finishes, the notice reports how many cells of the top alternative match the puzzle's known answer. The answer is used only for that count and never fills the grid. The grid was generated from common English words by `scripts/build_sample_puzzle.py`.

**How codeword solving works** (next to **Try a small example**) opens a page in a new tab that shows the solving stages and steps through a strict search on a small example. You can confirm or release letters in its example grid to see how the search changes. The page is `static/how-it-works.html`; it uses no server data and also opens directly from the file.

To create your own puzzle:

1. Choose a language. For a drawn puzzle, set dimensions and choose **Create new grid**. For a screenshot, add the image directly; the app detects the main grid and updates dimensions.
2. Click cells and use the inspector to enter their number and/or known letter. Use **Draw black** to toggle unusable cells. Numberless usable cells are allowed.
3. Screenshot upload immediately shows the original image and automatically recognizes the main regular grid, numbers, and black cells. Photo clue areas remain visible and are excluded from solving; shaded answer cells remain usable and are shown in green. Shading does not affect solving. Recognition can mistake a colour cast on a photo for shading; select the cell and switch **Shaded cell** in the Selected cell panel (Edit mode) to clear or set it by hand. In a straightened photo, a tinted cell without a printed number, including dark teal or navy fills, is read as a block. Review the transcription before solving. Set the number-position menu above the grid to the corner where the puzzle prints its numbers (top-left by default); image reading uses it, and over the image the app shows its own numbers in the opposite corner so they do not cover the printed ones. If automatic detection fails, expand **Manual adjustments**, set Rows and Columns above, and use **Apply rows and columns to image**. Edit Left, Top, Width and Height together, click **Apply alignment**, then choose **Read grid from image again**. Manual adjustments are collapsed by default; overlay opacity remains visible. Invalid alignment values stay editable until corrected. For a photo taken at an angle or of a curved magazine page, choose **Straighten photo**. The app looks for the grid's printed outer border and places the corner handles and five points per edge on it; check that the outline follows the border and drag any handle that is off. **Find border again** repeats the search and replaces moved handles. If no border is found, the handles start as an inset rectangle: drag the corners onto the grid's outer corners and the edge points onto the border. Where an edge curves more than one point can follow, as near the spine of a magazine, click the outline to add points (up to eight per edge) and drag them onto the border; double-click a point or press Delete to remove it. When the photo cuts off a corner of the grid, drag its handle just past the photo's edge to where the corner would be. The outline always shows the border exactly as it will be flattened. Then choose **Apply**. The photo is flattened, each grid line is followed cell by cell so the cells can be evened out and the overlay lines up even on a wavy page, and the grid is read again. Handwritten letters are not read; enter the letters you know yourself. After any recognition, numbers that may be wrong are shown in amber and playable cells without a recognized number show a red **?**; entering the number clears the mark. Impossible readings such as 114 in a puzzle numbered up to 25 are repaired (to 14) when that number is used elsewhere, and are always marked.
4. Set partial-word boundaries if needed. Drawn grids start with closed boundaries, including corners. Mark only endpoints that continue outside the captured puzzle. OCR currently leaves these flags closed; cropped continuations need manual marking.
5. Select dictionary use and mapping rules, click **Solve**, and review the alternatives.
6. **Save puzzle** stores the full workspace locally. **Open** lists saved puzzles with their language and date, newest first; the **Language** filter shows only puzzles in one language. Open restores a puzzle and includes rename and delete icons beside each one. Deletion moves the saved file to `data/trash/puzzles/` for manual recovery. **Export JSON** and **Import JSON** provide portable copies.

The workspace is backed up automatically to `data/autosave.json` a moment after each change and restored when the page opens, so a reload or closed tab does not lose work. With changes that are not yet saved or exported, the browser asks before leaving the page. **Save** still keeps named puzzles.

### Generate a puzzle from your own grid

The app can fill a grid you draw and turn it into a codeword to solve here or print.

1. Choose a language, set dimensions and choose **Create new grid**. Make cells black with Space or **Black / unusable**. Every letter cell must be part of a word of at least two cells, and word ends must stay closed.
2. Optionally enter numbers and letters in Edit mode. They are kept: cells with the same number get the same letter, different numbers get different letters, and letters you enter are given in the finished puzzle.
3. Choose a **Difficulty** (default Medium). It sets **Starter letters** to 3 for Easy, 2 for Medium and 1 for Hard; you can change the number afterwards (0 to 10). Starter letters are given in addition to the ones you entered, and a given letter shows in every cell with its number. Easy starts from frequent letters, which fill many cells, and Hard from rare ones.
4. Optionally list **Words to include**, separated by spaces, commas or new lines (up to 30). They are placed first and the rest of the grid is filled around them. Each needs a grid word of the same length. A word that is not in the dictionary is still used, for this puzzle only, and the status line says so.
5. Choose **Generate puzzle**. Every word is taken from the language dictionary (plus your listed words) and no word is used twice. The other cells are numbered so each letter has its own number, starting from the smallest numbers you did not use. The search tries random fills with restarts for up to 20 seconds and can be cancelled. It works on a drawn grid only, not on an imported image.
6. The finished puzzle is solved the way a person would, to grade it:
   - **Easy:** words that only one dictionary word fits, given the letters known so far, solve the whole grid one after another.
   - **Medium:** this also needs single letters: a cell where every fitting word has the same letter.
   - **Hard:** those steps alone do not solve the whole grid, so a solver has to try letters.

   For Easy and Medium, letters are given, each time the one that fills the most cells still unknown where deduction stops, until the puzzle reaches the level. Solving by deduction alone also proves that only one answer fits. A Medium or Hard request can come out easier; then up to six sets of starter letters are tried and the closest is kept. The status line always reports the level reached, and says so when it differs from the one asked for.
7. For Hard, **Only one answer fits** (on by default) also applies: the numbered grid is then searched for every answer the dictionary allows, with repeated words allowed as a solver would. While a second answer fits, a letter that tells the two apart is given and the grid is searched again. This check also has up to 20 seconds. The status line says how many letters were added and whether a single answer was confirmed.
8. The puzzle opens in **Puzzle** mode with the starter letters given. **Check my letters** compares the letters you have confirmed with the answer and outlines wrong ones in red. Suggestions are not checked. The answer is never written into the grid.

The bundled demonstration lists are too small for most grids; import a dictionary first ([dictionaries.md](dictionaries.md)). The puzzle only uses words from that list, so names or rare words in it can appear. If no fill is found within the time limit, that does not mean none exists: try again, or add black cells to shorten long words. Only when the search has tried every option does it report that no fill exists with the current dictionary. A single answer is confirmed only when the check has tried every option, and only within the dictionary used: a solver with a larger word list can still find another valid fill. If the check stops at its time limit, the puzzle is kept and the status says that a single answer is not confirmed. Without **Only one answer fits**, a Hard puzzle keeps exactly the starter letters you asked for and is not checked for other answers. The grading uses the same dictionary: with a very large word list full of rare words, few words have only one possible fill, so puzzles grade harder than they feel and Easy needs more letters. A common-word list matches how people solve much more closely. Word familiarity itself is not measured, because the dictionaries hold no word frequencies, and the grid you draw (long words, few black cells) also affects how hard a puzzle feels. The printed sheet shows the difficulty beside the title.

The answer and numbering are saved with the puzzle. They apply as long as the black cells and numbers are unchanged; after such an edit, **Check my letters** and the solution sheet are no longer offered.

### Print or save as an image

**Print or image** in the header previews the puzzle as a printable sheet: the grid with its numbers and the letters entered in Edit mode, a number key and an alphabet with the given letters crossed off. Answer letters and suggestions are left out. **Number key and alphabet** can be switched off. For a generated puzzle, **Solution sheet** adds a second sheet with every letter. **Print** prints the sheets on separate pages, **Save PNG** saves each sheet as an image at three times the preview size, and **Save SVG** saves scalable vector files. Everything is drawn in the browser.

### Hosted guest and user mode

A hosted server ([railway.md](railway.md)) can start visitors in **guest mode**. The header shows the current mode. Guests can create, import, edit and solve puzzles, but nothing is saved on the server: **Save puzzle** and **Open** are hidden, and **Export JSON** and **Import JSON** keep copies. The automatic backup stays in this browser (IndexedDB), so a reload restores the workspace on the same device. Guests start with the bundled demonstration vocabularies, never the server's saved dictionaries. Dictionary imports and edits apply only to the current browser session, are limited to 200,000 words and 4 MB per list, and are removed after two hours without use or when the server restarts.

**User mode** opens a password prompt. With the access password, **Save puzzle**, **Open** and dictionary changes use the server's persistent storage, exactly like the local app. Everyone with the password shares the same saved puzzles and dictionaries. The puzzle on screen stays open when you switch modes. **Leave user mode** returns to guest mode. In hosted mode the automatic backup stays in the browser in both modes, so people sharing a server do not overwrite each other's recovery copy. A server configured without guest access asks for the password before the workspace opens.

Keyboard controls: arrow keys select cells; digits enter a number and letters enter a known letter. The first digit replaces the existing number; consecutive digits entered within a short interval append up to 99, since no alphabet needs more numbers. Backspace edits an active number entry (otherwise clears the letter), Delete clears the letter, and Space toggles a black cell. Clicking or moving to another cell resets numeric entry. The inspector also edits numbers.

Use **Fit puzzle** to fit both dimensions, **Fit height** to fill the available height, or **Fit width** to fill the available width. The single-dimension modes allow scrolling in the other direction. Use the zoom buttons/slider to enlarge details. Zoom changes only the view; image alignment and puzzle contents stay the same.

## Edit and Puzzle modes

Use **Edit** for number/letter entry, Space or the Black / unusable checkbox, and grid alignment corrections. **Puzzle** allows answer-letter entry and deletion, but locks numbers, black cells, prefilled letters, dimensions, boundary controls and image alignment. Letters entered in Edit mode are marked as prefilled; player answers retain their editable status across save/open. Selection, zoom, solving and explicit confirmation/status actions remain available. Switch back to Edit to correct the grid.

Irregular cross-shaped imports retain their full grid bounds and exclude disconnected number-key rows. Borderless outside regions remain transparent and unusable. Recognition still requires review. Disconnected rectangular key tables inside the puzzle bounds, including upper-right panels, and their borderless surroundings are excluded from playable cells. Their printed glyphs remain available to the OCR cross-check before exclusion.

Numbers are read by consensus across the whole puzzle, not cell by cell. Each cell's corner number is cleaned of grid-line slivers and split into digit glyphs. Near-identical glyphs are clustered, and each cluster is labelled from Tesseract readings of its averaged shape plus the per-cell readings it contains. A cluster with weak evidence may take a neighbouring cluster's digit only when that makes the numbers a more complete 1..N sequence. Diagnostics list missing numbers in 1..N. To check recognition against your reviewed puzzles, run `python3 scripts/benchmark_ocr.py` (add `--auto` for automatic grid detection). It reads `data/puzzles` locally and never writes.

## PDF upload

Use **Add image or PDF** to import a PDF up to 8 MB. Choose a page for multi-page documents; single-page PDFs import directly. The selected page is rendered locally, then uses the same grid detection, OCR, manual alignment and zoom as images. Save/export stores the rendered page with the puzzle. Password-protected or damaged documents are rejected.

PDF import requires the Poppler commands `pdfinfo` and `pdftoppm` on PATH (`brew install poppler` on macOS; `sudo apt install poppler-utils` on Ubuntu). Pages are rendered with their longest edge at 3000 pixels. Processing is bounded and does not execute PDF scripts.

## Dictionaries and language rules

There is one customizable dictionary per language. **Edit language dictionary** opens a search: plain text finds words that start with it, `?` is one letter and `*` any number of letters (`K?TT*`, `*NING`). Filter by all, enabled or disabled words. Tick or untick a word to enable or disable it, delete it, or add words separated by spaces. These changes save immediately. Disabled words stay in the dictionary, are stored in `data/dictionaries/<language>.disabled.json`, and are skipped by solving, candidate search and pattern search; a word lookup reports them as disabled. **Bulk edit and import** holds the full paged text editor and file import. The bundled vocabularies are **small demonstration lists**, not general-purpose dictionaries. Import your own UTF-8 file with one word per line to solve real puzzles with broader coverage; [dictionaries.md](dictionaries.md) lists free sources and how to convert them. The dictionary editor supports adding or removing individual entries. Lists are normalized to uppercase NFC, deduplicated, and restricted to letters in the selected alphabet. Include inflections, compounds, and names you want recognized. UTF-8 imports support up to 1,000,000 lines and 16 MB. Choose the file, then select **Save dictionary**. The editor displays 1,000 lines per page; Previous/Next let you edit a large list without loading it all into one text box, and Save includes every page. Import keeps usable alphabetic entries and reports skipped lines and duplicates; it does not strip punctuation or turn hyphenated entries into different words. An import with no usable words leaves the existing dictionary intact. English and Dutch use A–Z; Finnish and Swedish also include ÅÄÖ. Dutch IJ occupies two cells. Dutch has a separate editable dictionary and unverified language-pattern suggestions. Finnish morphology controls appear only for Finnish puzzles.

Disable **Use dictionary**, then click **Solve** to explore language-pattern guesses. For standard one-letter-per-number puzzles, the app optimizes whole number-to-letter mappings across all intersecting words using bounded simulated annealing and repeated starts. It scores words with a per-language character model (letter sequences up to four long, including how words start and end) plus soft spelling rules such as vowel harmony, consonant runs, Q without U, and Finnish word endings. Each run's best mapping is polished until no single change improves it, and the alternatives shown differ from each other in at least three numbers (fewer on very small grids), so they are separate guesses rather than one guess with a letter or two swapped. How well this works depends on the grid. The score adds up over every word, so on a full-size codeword, where each number appears in many crossing words, the real mapping tends to score highest; in testing on several full-size puzzles, **Deep** search without a dictionary solved the grid, while **Quick** search was not enough. On small or loosely connected grids the score says little: on two small test grids with a known answer (10 and 7 words), the best guesses outscored the real words. A higher score means more typical letter patterns, not proof of the answer. Suggestions are **unverified letter sequences** and may not be real words; check them against the clues or a word list before confirming. Turning off **Use dictionary** while search time is **Quick** switches it to **Deep**; you can switch back. During the search the grid shows the best guess so far in a different colour, from the first fraction of a second, updated up to five times a second. **Shade letters by how sure the search is** (below the grid, on by default) compares each number's letter with its best rival letter: coral means the rival scores within 5 pattern-score points (check these first), light coral within 15, and unshaded a clearer lead. Hover a cell to see the rival and the gap. The shading follows the live guess while the search runs, recalculated about once a second, and then the selected alternative. On the benchmark grids every wrong letter in the top alternative was coral, together with a few right ones. Shading is not proof: an unshaded letter can still be wrong. It appears only for searches without a dictionary. The search is often settled within a second, so after it finishes, **Replay search** under the grid steps through each improvement it found (at most 60, evenly spread), with the same shading: press Play, drag the slider or use the arrow keys on it. Replay changes only the grid; clicking a cell or **Show result** returns to the result. The replay is kept for the latest solve only and is not saved with the puzzle. Variant mappings retain bounded word-candidate search.

Every suggested word shows a pattern check: **Typical**, **Unusual** or **Implausible**, with the rules it triggered on hover. The check compares letter patterns only. A typical pattern is not proof the word exists, and names, loanwords and compounds can look unusual. With a dictionary in use, the model is also adapted to that word list: it ranks dictionary candidates, ranks hypotheses that contain words missing from the list, and flags unsupported words with implausible patterns, which often point to a transcription error. The English model is trained on Webster's Second International (public domain), the Finnish model on the Kotus Nykysuomen sanalista 2024 (CC BY 4.0) with rule-generated case endings, the Dutch model on the OpenTaal word list (BSD / CC BY 3.0, accents removed for letter statistics only, so IDEEËN counts as IDEEEN), and the Swedish model on the SALDO full-form lexicon from Språkbanken Text (CC BY 4.0); see `app/models/README.md`. On a synthetic benchmark (14 words sharing one number key, quick search, eight runs), dictionary-free letter accuracy rose from 6% to 31% in English, from 22% to 46% in Finnish, from 36% to 40% in Dutch and from 12% to 30% in Swedish (Dutch and Swedish benchmark words held out of training) compared with hand-tuned scores.

Confirmed number mappings also produce provisional deductions even when a complete solution is unavailable. Review them and use **Accept mapping deductions** to confirm them. Search outcomes and errors are displayed beside Solve.

Finnish vowel harmony is a soft preference because compounds and loanwords can be exceptions; see [Kielitoimiston ohjepankki](https://kielitoimistonohjepankki.fi/ohje/vierassanojen-taivutuspaatteen-vokaali/). Other scoring weights are implementation heuristics, not linguistic prohibitions.

Mapping defaults to one letter per number and disjoint letters across distinct numbers. Raise **Letters per number** for variants where repeated occurrences can use different letters. Disable letter uniqueness to allow different numbers to share a letter. Each cell still holds exactly one letter.

Forbidden and discouraged patterns are optional; most puzzles need neither. Type letters only, one sequence per line or separated by commas (up to 40 letters each, at most 100). A sequence matches anywhere inside a word, with no wildcards or regular expressions: `Q` matches every word containing Q, `AA` every word with a double A. Forbidden sequences reject candidates; discouraged ones lower a word's ranking once per occurrence. Neither list contains asserted universal linguistic bans by default. Preferences and defaults are conservative so unusual valid names or compounds are not silently excluded.

## Finnish inflected forms (optional)

Selected-word search can include an independently built Kotus/Omorfi form index. Enable **Use dictionary**, then **Local inflected words** in Puzzle setup. The setting applies to selected-word search and full-grid Solve. Expand **Base words, grammatical forms and sources** beneath results. Grammatical descriptions are shown beside the lemma; raw Omorfi tags are preserved in API evidence. The index supplements the editable word list; deleting a word from that list does not delete index entries. Disable this option to search only your edited list. Full-grid Solve also uses the enabled local morphology index.

Building the index takes Omorfi and native HFST; see [dictionaries.md](dictionaries.md#optional-inflected-finnish-forms). The index and its models stay under the ignored `data/morphology/`, and searching it is fully offline. Its explicit coverage is nominal cases (singular/plural) and active indicative present/past verb forms. Generation failures remain gaps; it never invents a fallback spelling. Comparative/superlative adjective generation, possessive suffixes, clitics, productive compound expansion and morphology matching at open fragment boundaries are outside this initial index. Each query has time, result and work limits. Absence is not evidence that a Finnish word is invalid.

## Look up a word or pattern

In **Explore selected words**, type a word to check it, or a pattern to search. In a pattern, letters are known, numbers are puzzle numbers (the same number is the same letter) and `?` is any letter, for example `A 12 12 K 5`. **Use selected word** builds the pattern from the selected grid word. With **Apply this puzzle's confirmed number mappings**, numbers already confirmed in the grid are fixed and their letters are unavailable to other numbers. With unique letters, typed letters also belong to another number, so `A 12 12 A` cannot match AAAA.

When every cell of the selected grid word has a letter (confirmed or from the displayed suggestion), the panel checks that word automatically. It shows whether the word is listed and its pattern score, so you can review a solved grid word by word. Words that continue outside the grid are not checked as complete words.

A word lookup always checks your word list (and, for Finnish, the local form index). It reports whether the word is listed, and gives its pattern score. Pattern searches follow **Use dictionary**: with it off, they return unverified pattern guesses. Each result, like each candidate in the selected-word results, says whether it is in your word list, part of a listed word (open word end), only in the Finnish form index, or a pattern guess. Each also shows its pattern score.

Pattern labels are calibrated per word length on held-out real words and letter-shuffled fakes, so a short word is not judged by long-word standards. Short words overlap heavily with random strings: most two- and three-letter words are labelled unusual, and the check says little about them.

## Full-grid search controls

**Quick** searches for up to four seconds of solver time; **Deep** permits up to sixty seconds and a larger node budget; **Extended** permits up to five minutes with a further increase in the node budget. The search time starts after preparation: loading the word list, adapting the letter model to it and indexing it for the puzzle. With a large list this can take a few seconds; the status then reads **Preparing:** and the step, and it does not use up the search budget. Cancel works during preparation too. Progress then shows the current stage, visited search nodes and elapsed time (including preparation). **Cancel search** requests backend cancellation and waits for the best available provisional result. If the new search has no useful result, existing suggestions stay visible. Search status reports whether time, nodes, cancellation or completion ended the search. Candidate and memory pruning are reported separately; more time cannot recover candidates excluded by those limits. Editing constraints or replacing the puzzle also cancels the old request and prevents late results from changing your workspace.

Before indexing, dictionary search keeps only exact word lengths present in the puzzle (or selected words). Open-ended fragments also retain longer source words. This reduces the working index without changing the saved dictionary; full-grid diagnostics show the retained entry count. Search indexes these words by length and repeated-letter pattern, then propagates crossing and shared-number constraints before branching. Strict search keeps the 12 highest-scoring complete solutions rather than the first 12 it finds, and skips branches that cannot beat the weakest of them. When it finishes, these are the 12 best solutions among the searched candidates; if it stops at the time or node limit, they are the best found so far. The diagnostics say when more solutions exist than are shown. Finnish morphology participates when enabled and available. Returned words distinguish editable-dictionary matches, morphology matches with source/analysis evidence, fragments, and unverified words. These labels describe supporting evidence, not proof of the intended answer.

Enable **Allow missing words** in Dictionary settings for printed puzzles. They usually contain names, brands and foreign words that no word list covers, so strict search rarely completes them. The fallback places listed words and minimizes the number of words without dictionary support; an unsupported word takes its letters only from crossings and number mappings. It first looks for a grid with at most one unsupported word and allows more only when that fails, then restarts after each improvement to look for a grid with fewer. The last quarter of the budget is kept for an unrestricted attempt, so a search that finds nothing better still returns a hypothesis. On a printed 13 × 13 Dutch puzzle with one word missing from the OpenTaal list, quick search now completes the grid in about a second; with ten more of its words removed from the list, deep search still recovered every cell that the remaining list and crossings determine. Letter-pattern checks rank hypotheses with the same number of unsupported words but do not exclude any: in tests they flagged only about half of the nonsense words and also flagged real abbreviations. Numbers that occur only inside unsupported words stay empty: the app then displays a partial, unverified hypothesis rather than inventing letters. Unknown-word search is bounded and may still fail or produce incorrect hypotheses. Adding reliable confirmed letters remains useful. On two printed Finnish test puzzles (about 70 words each) quick search found the same hypotheses as deep search.

Candidate lists and morphology queries are bounded. Longer search does not guarantee all vocabulary is considered or that the intended answer will be recovered. Source labels survive only while supported: on loading saved suggestions, current dictionary matches are rechecked and other constraint-compatible words remain unverified.

The browser uses in-memory jobs at `/api/solve-jobs`; the synchronous `/api/solve` endpoint remains available. Finished jobs expire after ten minutes and at most sixteen are retained; solver/import work shares the existing concurrency limit. No source images or saved puzzle files are written by a search.

## Confirmation and undo

The solved-word list supports evidence filters and sorting. **Most uncertain first** prioritizes unsupported words, then morphology/fragment matches, then dictionary matches, using pattern assessments and scores within each group. Lower pattern scores are less typical; they are not confidence percentages. **No dictionary match** means this result has no full-word dictionary evidence, including unchecked guesses. Click a word to select and reveal its Across or Down cells in the grid.

Word rows show only available confirmation actions. Partially confirmed words can offer both **Confirm** and **Unconfirm**, with tooltips explaining each action; locked prefilled letters stay protected in Puzzle mode.

Use **Confirm** to turn a provisional letter into a fixed constraint. **Unconfirm** releases the constraint and keeps the letter as a provisional guess, which is saved but ignored by the solver. Word rows support confirmation and unconfirmation; the cell inspector also provides an action for every occurrence of the selected number. If another occurrence still confirms that mapping, a released cell remains a mapping deduction.

To correct a misread number after solving, change it in Edit mode. The suggestions stay: in each one the cell takes the letter that suggestion gives the new number elsewhere in the grid, or stays empty if the number appears nowhere else. The cell's own letter belonged to the old number and is cleared, also when it was entered in Edit mode, so one letter never ends up on two numbers; if a printed letter was the correct one, type it again after fixing the number. If the new number already has a confirmed letter, the cell shows it as a mapping deduction for you to confirm. Suggestions that contradict confirmed letters are dropped. Solve again to check the adjusted suggestions. Other changes to the grid still clear the suggestions.

With one letter per number, deleting a letter from a cell whose number shows that letter in other cells removes it from the whole number, after you confirm; **Undo** under the grid restores it. Otherwise the other cells would keep showing the letter.

**Undo last confirmation** restores the previous acceptance state, including a bulk acceptance. This history is limited to the current session and is cleared by unrelated constraint edits, loading another puzzle or running a new search. Unconfirming is available for letters entered manually as well. Mapping deduction is computed automatically from the remaining confirmed letters.

## Ruled-out letters and wrong words

Tell the solver what an answer is not. These controls are advanced, so they start collapsed. Select a cell, open **Rule out letters** and use **Rule out** to say its number cannot be a letter; solving and searches then never use that letter for it. Under **Number ↔ letter**, open **Ruled-out letters**: its heading counts what is ruled out and suggested, and **Probably not** lists letters that would form a run practically never seen in words of the language next to the known letters: in `1 1 K 20 K 6`, 20 is probably not W because KWK hardly occurs in Dutch. Hover a letter for its run and click it (or **All**) to rule it out. These suggestions are pattern checks, not proof, so they are never applied without your click.

When a suggested word does not fit its clue, use **Wrong** in the word list or **… is wrong here** next to **Add to list** for the selected word. Solving and selected-word searches will not suggest it in that position again; the dictionary is unchanged. Click a ruled-out letter or rejected word to allow it again. Ruled-out letters and suggestions are listed only for numbers that show no letter yet (confirmed, suggested or mapped); they are kept and come back when the number is open again. Both lists are saved with the puzzle, and **Reset puzzle** clears them.

## Search and recognition limits

- Search is bounded by time, nodes, candidates, alternatives, and memory. Ranking applies to explored candidates and is not a guarantee of the global optimum. Failure to find a result is not proof a puzzle is impossible.
- Large or weakly constrained grids need known letters and suitable dictionaries. The app prioritizes an editable working flow over exhaustive solving of difficult newspaper puzzles.
- Open boundaries use dictionary prefixes, suffixes, or substrings. A fragment is not presented as a complete verified word.
- Automatic recognition targets axis-aligned, regular rectangular grids with visible grid lines. The main puzzle grid is selected separately from headers and a smaller number-key table. Tilted or curled photos need **Straighten photo** first; handwriting recognition remains unsupported, and printed numbers touched by handwriting are often misread. OCR can miss or confuse small numbers and prefilled letters, especially Finnish diacritics. Photo clues are preserved visually, not semantically interpreted; enter any inferred answer letters yourself.
- Grid dimensions are limited to 40 by 40. Screenshot upload in the UI is limited to 8 MB; decoded images must fit within 16 megapixels. Server requests are capped at 20 MB.
- By default the server binds only to 127.0.0.1 and rejects foreign hosts/origins; it is intended for a trusted local computer. The opt-in hosted mode is described in [railway.md](railway.md). Its user mode has one shared password, not separate accounts.
